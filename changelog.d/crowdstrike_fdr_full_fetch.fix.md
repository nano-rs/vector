The `crowdstrike_fdr` source no longer duplicates events when one object of a batch fails mid-download. Each object is now downloaded completely, in its own task, and verified before any of its events is emitted (objects past `spool_threshold_bytes`, default 64 MiB, spool to `data_dir`), so a backed-up pipeline never leaves a GET half-read and `checksum: verify` emits nothing from an object that does not match. A failed GET, a body cut short or stalled, or a checksum mismatch is tried again inside the hold (`fetch_max_tries`, default 4, with `fetch_retry_backoff_secs` doubling from 1 s); the batch is released only when one object has used every try. Each file is recorded as delivered in `data_dir` once its events are acknowledged, and a re-delivered batch skips those files, so a release repeats at most the files that were in flight (NAN-5005).
